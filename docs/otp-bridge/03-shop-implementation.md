## Portfolio changes

`0062_shop_otp_bridge.sql` adds four tables: `shop_otp_inventory_aliases`, `shop_otp_grants`, `shop_otp_lookup_attempts`, `shop_otp_session_proofs`. Historical duplicate migration prefixes are preserved. Binding unit/alias and grant allocation/unit/alias are lifetime UNIQUE. FKs preserve grant audit with RESTRICT; only session proof cascades with its ephemeral session. Triggers reject identity rebinding, deletion and resurrection of terminal grants.

Binding states: ready -> disabled/quarantined; V1 API does not re-enable or reassign. Grant states: pending -> active, active/pending/suspended -> revoked/expired; revoked/expired are terminal. A fulfilled-allocation transition captures pending metadata atomically after verified identity and payment. Maintenance and owned order rendering reconcile guest linkage and pending grants; remote validation may fail without blocking credential fulfillment. At most ten remote validations/run, versioned 60-second lease and exponential backoff from 60 seconds to one hour, maximum twenty attempts per cycle. Exhausted pending records have a 15-minute cooldown before an audited recent-admin revalidation may begin a new bounded cycle; lifetime attempt count and failure metadata remain. Missing/disabled providers remain pending.

Live joins require paid and paid_at, eligible processing/fulfilled order, partial/fulfilled order delivery, exact item/allocation/unit/variant, fulfilled timestamps/statuses, matching ready binding, active undeleted activated customer and a verified email identity matching the order email snapshot. A bearer guest-order token alone grants no OTP rights. Existing key-reveal and payment implementation remain intact; E2E extends the real checkout/payment/delivery path with entitlement assertions.

The same customer session completes explicit existing Google/magic-link reauthentication. The original session hash/customer identity are bound in the one-use challenge; callbacks do not switch identity or issue a replacement cookie for step-up. Proof is server-stored for ten minutes. Google requires signed RS256 ID token from pinned Google certificates endpoint, correct issuer/audience/subject/nonce, fresh auth_time and iat (120 seconds), unexpired exp; max_age=0 is requested. If Google does not supply sufficient fresh auth_time, denial is required; magic-link remains the existing alternative. Normal login remains unchanged.

D1 uses atomic INSERT SELECT reservation before RPC: 5 seconds/grant, 30/sliding five minutes/grant, 150/sliding day/customer and 150/sliding day/HMAC-hashed IP. Twenty/fifty concurrent attempts cannot exceed a slot. Audit stores only IDs, hashed identity, time, safe outcome and capped latency. Pending attempts become abandoned; old attempts prune after thirty days in batches of 200. Integration timeout is three seconds; malformed outputs fail closed. Audit finalization precedes the last authorization query.

Migrations `0063_shop_otp_entitlement_policy.sql` and `0064_shop_otp_validation_recovery.sql` complete the reviewed sold-term and recoverable retry state. Explicit variant policy is snapshotted on order-item insertion inside checkout, then immutably copied to the grant at issuance. Service term start is max(payment, fulfillment), while message eligibility additionally respects verified customer identity/account activation/ownership linkage. Null expiry is allowed only for an explicitly sold perpetual policy; unclassified historical grants are suspended and cannot be repaired by changing a future-sale policy. Guarded, audited extension changes only effective expiry before the existing term ends; terminal/expired grants cannot return. See report 07 for authoritative source decisions and migration/expiry race evidence.

Protected existing admin API, `/api/admin/shop/otp`: GET `?inventoryUnitId` reports safe binding/grant/aggregate outcomes; POST `/bind` accepts unit ID, alias ID, compiled provider key; POST `/disable`, `/quarantine`, `/revoke` accept unit ID and bounded reason code. POST `/policy` snapshots an explicitly reviewed variant term for future purchases; POST `/extend` admits one live-term extension at the expected version; POST `/revalidate` recovers an exhausted validation cycle after cooldown. Existing Access/password/session/CSRF router gate plus recent password session (30 minutes) applies. Grant revoke is recorded before binding change, preserving operator reason in one D1 batch. No customer OTP is returned. V1 supplies single-unit provisioning only; any future bulk operator tool must prevalidate a protected out-of-repo mapping, duplicates/references and dry run first. Credentials/TOTP must never be parsed to infer mappings.

Per-allocation React island extends existing authenticated order detail with VI/EN/JA/ZH strings and existing design tokens. Poll every five seconds for max 120 seconds, one loop/card, abort in-flight work at deadline/hidden/navigation/logout. Code stays in component memory and clears at receipt age cap; no storage/analytics/URL code. Same-origin BroadcastChannel carries only literal logout to clear other tabs. Keyboard, aria-live, copy/error/reauth states and mobile widths are tested in Chromium and WebKit; these are browser-engine emulations, not physical Safari certification.

Wrangler named binding survives Astro build/postbuild; both flag defaults are false. Types generation copies actual config to ignored secret-free directory and uses Wrangler; optional secret names remain in existing runtime augmentation. Astro 7.3.8, Cloudflare adapter 14.3.4 and Wrangler 4.150.0 are within their existing major versions, updated to remediate observed advisories; pinned Miniflare 5 beta is the runtime used by Wrangler and test harness uses its supported V4 option converter. Audit at validation time reports zero known vulnerabilities. This broader lockfile/type diff requires reviewer attention.
